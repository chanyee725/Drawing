# Eraser 예시 종합: 배치 규칙·스타일 토큰·구현 티켓 (09)

> `09-examples/A~E.md`(공개 예시 35개 + 목록 페이지)를 하나로 합쳤어요. 새로 잰 값은 없고, 다섯 파일의 측정값만 썼어요.
> 기준일 2026-11-13. 우리 쪽 비교 기준은 develop `1f3bb6c`(`fix/crisp-diagram-blocks` 병합 뒤)의 `shared/render`(ELK layered)예요. 설계 문서 E16의 "기준점"과 같아요.
> 캡처·측정 원본(`layout.json`, `styles.json`, `embed*.png`, `ours.png`)은 저장소 밖 `eraser-ref/<slug>/`에만 있어요. Eraser 파일(JS·CSS·폰트·아이콘)은 가져오지 않았고 숫자만 옮겨요.
> 근거 표기: `A`~`E`는 `09-examples/A.md`~`E.md`, 그 뒤는 slug예요. 예: `D campus` = D.md의 `campus-network-university`.

## 0. 전제

1. **Eraser 예시는 자동 배치가 아니에요.** 35개 모두 embed의 `#map-present-data`에 요소마다 `x, y, width, height`, 선마다 꺾임점 `points`와 `labelPlacement`가 저장돼 있어요(A·B·C·D·E §0). 사람이나 생성기가 손으로 찍은 **저작 좌표**예요.
2. 그래서 목표는 "같은 그림"이 아니라 **"손으로 정리한 것처럼 보이는 규칙"**이에요. 우리는 ELK(layered)로 먼저 놓고, 아래 §1 규칙을 **후처리**로 적용해요. ELK 옵션만으로 안 되는 것(열 공유, 격자, 같은 크기 띠)은 후처리가 맡아요.
3. 좌표는 2px 격자 100%(D), 4px 격자는 15~88%로 예시마다 달라요(B·D·E). **엄격한 격자 스냅은 없어요.** 우리도 2px 반올림만 해요.
4. 글자는 저작값 × 0.87로 그려져요(14→12.18, 15→13.05). 아래 토큰은 모두 **화면 px(world)** 값이라 우리는 배율 없이 그대로 써요.
5. **다크 모드가 없어요.** 35개 모두 `theme: "light"`이고 `prefers-color-scheme: dark`·`?theme=dark`에도 흰 배경이에요(A·B·C·D·E). 다크는 §2.3에서 우리 안을 제안해요.

## 1. 배치 규칙 (ELK 후처리로 흉내 내기)

### 1.1 노드 크기: 고정 폭, 한 뷰에 1~3종

| 규칙 | 값 | 근거 |
|---|---|---|
| 폭은 텍스트에 맞추지 않아요 | 폭 버킷 **160 / 200 / 260** 중 하나 | A health-plan 180×58 ×23, A capability 280×52 ×28(100%), C fedramp 200×60 ×90, C pci 152×52 ×69, E hospital 160×64 16/18, B ai-gov 260×56 ×19 |

| 높이 | 1줄 **52**, 제목+부제 **56**(넓은 카드 64), 칩·범례 **32~40** | B 전체 1,189개 중 56: 499, 52: 335. D "56/60 기본, 칩 32/40" |
| 같은 그룹·같은 층 = 같은 크기 | 그룹(또는 rank) 안 최대 버킷으로 통일 | B 같은 x 공유 0.82~1.0, E "한 열·밴드 안 같은 폭·높이" |
| 넘치는 글 | 3줄까지 감싸기(`balanced`), 그래도 넘치면 다음 버킷 | B·C·E `data-text-max-lines=3`, `text-grow-policy=balanced` |

### 1.8 후처리 순서 (구현 안)

1. 크기 버킷 정하기(§1.1) → ELK 입력에 고정 크기.
2. 선 없는 그룹·노드 분리(§1.4) → ELK는 연결된 부분만, 격자는 따로 계산해 자리를 예약.
3. ELK 실행(간격 §1.5, 패딩 §1.6, `considerModelOrder` + 층 안 순서 강제).
4. 정렬 스냅(§1.3): 층 중심 맞춤, 열 x 공유, 2px 반올림.
5. 띠 맞추기(§1.2): 형제 그룹 폭·높이 통일, 부모 다시 감싸기.
6. 선 다시 그리기(§1.7): 포트 균등, 직선 우선, 꺾임 ≤ 2, 버스, 라벨 자리.

같은 코드 → 같은 SVG(결정적)는 그대로 지켜요. 100개 노드 150ms 예산(E3)도 유지해요.

## 5. 재생 effects → 진행판(E25) 참고

Eraser 흐름 재생은 `flows[].steps[].animation.effects[] = { ref, type, start, stop(ms), easing }` 하나로 표현돼요(A·B·C·D·E). `travel-line`은 선을 따라 파란 선이 그려지고 800ms `ease-in-out`, `pulse`는 노드 테두리 강조 700ms, `shake`는 지적·장애 표시예요. 다음 효과가 앞 효과 끝나기 100~200ms 전에 시작해 이어져 보여요(선 0–800 → 노드 700–1400 → 다음 선 600–1300). 재생 중에는 이번 단계와 무관한 요소를 20~25% 불투명도로 흐리고, 지나간 선은 `#2866DF` 계열로 굵게 남기고, 현재 노드는 파란 이중 테두리 + 왼쪽 위 번호 동그라미 + 옆 말풍선, 아래에 `1 / 5`·점·이전/재생/다음 막대가 떠요(B ai-gov). E25에는 이렇게 옮기면 돼요: 진행 중 단계 = `pulse` 반복, 끝난 간선 = `travel-line` 한 번 뒤 진하게 남김, 막힘·실패 = `shake` 한 번 + 빨간 배지(E41), 대기 = 흐리게. 효과 목록은 Eraser처럼 `{ref, type, start, stop}` 배열로 두면 E24의 단계↔노드·선 키에 그대로 붙어요. `prefers-reduced-motion`이면 움직임 없이 색·배지·기호만 바꿔요.
